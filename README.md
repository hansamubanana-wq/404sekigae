# 404 席替え

404 の席替えアプリ。three.js の 3D 演出で、2人ずつ席を発表します。

ネオンが光るステージの床に、机の柔らかい影を焼き込んでいます。名前札は青とピンクの配色で文字を読みやすくしています。発表中は対象の席を明るく保ち、周りの机と名札はネオンの光を残しながら約0.4秒かけて明るさが変わります。司会者の足元の影は歩き方や曲の拍に合わせて変化します。 床には光る格子が走り、曲の拍ごとに光の波が手前から奥へ流れます。奥は光る霧に溶け、ゆっくり動く光の帯が流れます。床はつやのある黒で、奥の霧と光の帯、ライトの光の筋、教卓の文字がうっすら逆さに映り込みます (光るものを床で上下に反転して加算で描く軽い方法)。ライトの光の筋は空気中に見え、中をもやがゆっくり流れ、細かい光の粒がきらめきます。

- 本番: https://404sekigae.vercel.app/ (main に入ると Vercel が自動で公開)
- iPad / iPhone / PC の Safari・Chrome 向け。ホーム画面に追加すると全画面のアプリとして使えます (PWA、オフライン対応)

## 使い方

| 操作 | 内容 |
| --- | --- |
| 選んだ席をロック | 席をタップすると鍵マークが付き、次の席替えでその席が固定される。もう一度タップすると解除する |
| 選んだ席でやり直し | 固定していない席を2つ以上選び「実行」。選んだ席だけでシャッフルし、通常の演出で発表する。他の席はその回だけ固定される |
| 手動で入れ替え | 固定していない2席を順にタップすると、その2人が入れ替わる |
| 選択を解除 / 閉じる | 選択を消す / モードを終了する。発表中は席の操作ボタンが隠れる |
| 席替えスタート | 固定していない席をシャッフル。司会者の登場に続いて、2人ずつ発表 |
| 履歴 | 席替え・やり直し・手動入れ替え・元に戻すなどの結果を、日時と操作名付きでこの端末に自動記録する（新しい順に最大30件）。履歴を選ぶと当時の席とロック状態に戻り、復元直前の状態も残る |
| 保存 / 元に戻す / 印刷 | 席を端末に保存 / 出席番号順に戻す / 2D の座席表を印刷 |

履歴は発表の合間に開ける。「保存」で指定した配置は、引き続き次に開いたときに読み込まれる。

URL のオプションは `?fps=30` で描画を毎秒30回に設定、`?q=low` で軽い画質、`?slow=0.2` で演出をスロー再生します。

3D の描画は既定で毎秒60回が目標です。Canvas と3Dの中間面は同じ解像度で、DPR は通常2、`?q=low` は1、描画面は最大約420万画素です。iPad A16 の横向き（2360×1640）は DPR 2 のまま描画します。発表中に描画の遅れが続くと、ブルームの処理解像度を縦横1/4から1/6にし、粒子を最大約2割減らします。安定すれば元に戻ります。画面と文字の解像度は維持します。

開始ボタンは準備が終わるまで無効です。読み込み画面で教室、名前と文字、3D 描画、音、動画の進み具合を表示します。壁のノイズを焼き込み、全員の名札・名前カード・粒子の文字マスクを GPU に転送し、演出用のシェーダーと小道具を先に描画します。机はインスタンス描画し、幕・風・ロケット・紙吹雪などの小道具は使い回します。最前列中央の動画を起動中に先読みし、取得できなければ発表時に通常の読み込みを試みます。

描画は WebGL（WebGPU には移さない・2026-11-25 決定）

## 席の決め方

最前列中央は男子の席として抽選します。女子が固定されている場合はロックを優先し、コンソールに警告します。最前列中央を動かす回に割り当てられる男子がいなければ、その回の抽選を見送ります。

制作者の土蔵さんの席は、男女の混ざり方の条件を満たす後ろ2列から抽選します。ロック中や、選択範囲などで後ろ2列に動かせる席がない場合は現在の席を維持します。

席替えと選んだ席のやり直しでは、上下左右の隣が2人以上なら同性・異性の両方、隣が1人なら同性がいる配置を選びます。斜めと空きマスは数えず、ロック席は動かさずに隣として数えます。
同性がつながる最大の塊は12人までが目安です（完全ランダム1万回の平均は約12.9人）。最大4,096回で条件に合う配置が見つからなければ、試した中で違反人数と最大の塊の人数を足した値が最少の配置を採用し、コンソールに警告を出します。

## 発表の進み方

- 初回は、リーゼントと蝶ネクタイ姿の手作りの3D司会者が、足音だけで左前から教卓の黒板側に歩く。“Ladies and gentlemen!” に続けて静かな教室で “Thank you all, for coming here today!” とお礼を言い、ひと呼吸置いて “MUSIC... START!!!” へ進む。“START” でBGMを始め、教室全体を約3.2秒映す。曲の冒頭の拍（112 BPM）に合わせてカメラと照明を軽く動かし、司会者の画角へなめらかに戻り、“The 404 seat shuffle starts NOW!” へ進む。“And first up is…” で発表へつなぐ。字幕は「MUSIC START!!」だけ英語で、ほかは日本語の2段表示。司会中は「教卓」の文字を隠す。
- 初回の司会は約31秒。同じタブの2回目以降は最後の台詞だけの約3秒版で、通常の音量でBGMを始める。台詞の終盤からWeb Audioで合成した上昇音を鳴らし、最初の発表で低音とシンバルを重ねてカメラを軽く揺らす。
- 足音は約0.65秒ごと。かかとの着地に合わせ、硬い床を革靴で歩いた録音から切り出した4種類を順に鳴らす。カメラと照明はBGMの実際の再生開始と112 BPMの拍を基準にし、小節の頭を強める。
- `mc.js` の `USE_KENNEY_MC` は `false`。手作りの司会者の表情と口パクを使う。Quaternius の Walk を手本に、短い歩幅で腰の高さを保ち、腕の振りを控えめにする。かかとの着地は録音に合わせる。外部モデルの読み込みは無効。
- `?intro=1` または `?beatOffset` を付けると、同じタブでも司会者の登場を毎回最初から再生する。`?beatOffset` のときだけ右上に調整ボタンが出る。±0.02秒ずつ即座に反映し、同じ端末の次回以降にも引き継ぐ。`?beatOffset=0.08` のようにURLで補正値（秒）を指定すると、その値から調整できる。正の値でカメラと照明を遅らせ、負の値で早める。
- BGM中は、名札が列ごとの時間差で小さく弾み、左右の揺れは2拍で1往復する。カメラは小節をまたいでゆっくり漂い、照明はなめらかに明るさを変える。盛り上がりの強弱は約1.5秒で切り替え、発表直後の札は動きを抑える。曲の切り替え中は両方の曲の拍を音量に応じて混ぜ、全体に同じ `beatOffset` を反映する。

| BGM | BPM | ファイル冒頭から最初の小節頭まで |
| --- | ---: | ---: |
| `bgm_main` | 112 | 0.014秒 |
| `bgm_tension` | 90 | 0.026秒 |
| `bgm_finale` | 124 | 0.036秒 |

最初の小節頭は、PCMに展開した音声のキック・スネア付近の帯域の立ち上がりを、曲ごとのBPMの格子に照らして測定。
- 右上の「スキップ」で司会の声と演出を止め、開始演出へ進める。“START” より前にスキップするとBGMは通常の音量で始まる。「選んだ席でやり直し」は通常の発表から始まる。
- 司会者の声は Google AI Studio の Gemini 3.8 Flash TTS（Mako）。3文を収録した13.28秒の音声を使い、字幕とカメラを声に合わせる。声が流れる間はBGMを絞り、モデル・音声・フォントは開始前に準備する。 [司会者の素材とライセンス](media/mc/CREDITS.md)
- 司会者は登場後も教卓の黒板側に立ち、体を軽く揺らしたり、まばたきしたりする。席が3〜4人分決まるごとに英語で合いの手を入れ、最前列中央の着地と全員決定でも話す。声に合わせて口と手を動かし、下の黒帯に英語の台詞を出す。合いの手は発表と同時に進む。
- 司会者はミトン型の手でマイクを包み、人差し指側から親指を添える。手首を一周する袖口、声に合わせて幅と開きが変わる口パク、視線やまばたき、歩きや音楽に少し遅れて揺れる蝶ネクタイ・裾・前髪を描く。
- **2人ずつ**発表する。固定した席の関係で2人組が余るときだけ、最後の組の直前に1人の回が入る
- **最後の3人**は通常「ラスト3人…」→ 候補の名前を表示 → 最前列中央を動画で発表 → 残りの2人を短い演出 (ポン + 弧) で発表する
- 発表の順番では、制作者の土蔵さんは9〜11番目のいずれか（10人未満なら最後）。最前列中央の席に決まった場合は動画もその順番で流す。
- 最前列中央の席を固定している回 (動画なし) は、最後の1人だけ「最後の1人…」のあと特別な演出で発表する
- 1回の発表は「**登場** (2人の名前カードを画面の真ん中に大きく出す) → 少し見せる → **移動** (それぞれの席へ)」。登場と移動はそれぞれ山札方式で、全部ひととおり出るまで同じものは出ない (`pair.js`)

演出の吹き出しは、台詞や合図を表示する。「ドーン！」や「発射！」などの擬音・演出音は音だけ鳴る。

## BGM

Gemini で生成した歌のない3曲を、ステレオの AAC（M4A）に加工して使用します。曲の読み込みとデコードは起動中に行い、切り替えは1.25秒のクロスフェードです。

| 曲 | 鳴る場面 |
| --- | --- |
| `main` | 初めて開いた座席表は無音。初回の “START” でBGMを始め、最初の約3.4秒で音量0.64から通常の0.36になじませる。発表後は座席表で音量0.20 |
| `tension` | 「ラスト3人…」など終盤のカウントから（音量 0.44）。最前列中央の動画中は BGM の音量を絞る |
| `finale` | 最前列中央のカードが着地したときから（音量 0.60）。中央の発表がない回は「全員決定！」から。座席表に戻ると小さめの `main` に切り替わる |

## 最前列中央の席の動画演出

最前列 (教卓側の1列目) の**中央の席** (`0-3`) を発表するときだけ、完成動画 `media/the_front_row.mp4` を流します。

流れ: **前振り → 動画 → 締め → 既存の結果表示**

1. **前振り**: 上下に黒帯が入り、照明が落ちて、スポットライトとカメラが最前列中央の席 (まだ「?」の札) に寄る。札の金枠が鼓動に合わせて光り、字幕「最前列の中央は……」→ 席の位置に向かって丸くすぼまるように暗転
2. **動画**: 黒から浮かび上がるように音付きで再生し、通常は操作なしで最後まで流れる
3. **締め**: 名前の出た終了画面を少し見せてから、ゆっくり暗転 → 教室に丸く開いて戻り、字幕「― 最前列 中央 ―」→ カメラを元に戻す
4. 既存の結果表示 (名前カードが席へ着地)

- 動画: 爆弾処理のパロディ (夜の倉庫・裸電球)。焦る女性と、焦りつつ余裕のある男性が、最前列中央の名前が入った装置のタイマーと向き合う。「YouTube で見た」で笑わせ、赤いワイヤーを切ってタイマーが 00:01 で止まる。装置の小さな画面が白く光り、カメラが寄って止まる。43.3 秒 / 1280×720 / 24fps / H.264・AAC
  - 4カット (各10秒) を Gemini アプリの Omni で生成して連結 (2カット目以降は前のカットの最後のコマから作成)。声は生成時の英語、日本語字幕は動画に焼き込み済み
  - タイマーの数字は全コマ描き直し、00:22 から1秒ずつ減ってワイヤーを切る約21秒で 00:01 に止まる
  - 37.5 秒から最後のコマを止め絵にして、3回の電子音 (37.55 / 38.55 / 39.55 秒)、心音2回、42.5 秒のノイズ音を動画の音に入れている
  - 差し替えたら `frontrow.js` の `src` の `?v=` を上げる (古い動画がキャッシュに残らないように)
- 白い画面の文字: 止め絵の白い画面に、**37.55 秒から 3・2・1**、2秒おいて **42.55 秒から名前** (その回の抽選結果 `seats["0-3"]`) を映し、終了画面まで残す
  - 画面の四隅 (`FRONT_ROW.quad`、実際の映像の矩形に対する割合) に合わせて `matrix3d` で傾けるので、モニターに映っているように見える
  - 字体は液晶風のドット文字 DotGothic16 (Google Fonts、起動時に先読み)。数字は出る瞬間にまたたき、名前は乱れた記号から約0.7秒で本当の名前に決まる。うっすら走査線を重ねる
  - 名前が長いときは、画面の幅に収まるよう文字を小さくする
  - 表示は再生位置で決める。判定は実際に画面に出たコマの時刻 (`requestVideoFrameCallback`) で行い、使えないブラウザでは `currentTime` を使う
- 仕掛け: 最前列中央が空席の間 (発表前) は、はてなの名札を出さず、机の真ん中に動画と同じ装置 (赤い筒の束・黒いテープ・基板・赤い数字のタイマー・小さな液晶・赤と青の線) を置いている (`bomb.js`)。字幕や演出では触れず、近くの席の発表でカメラが寄ったときに映り込むだけ
  - 席替えを始めるとタイマーが動き出し、**動画が始まる瞬間にちょうど 00:22** になる。最前列中央が何組目かから残り時間を見積もり (1組あたり実測約7.4秒)、各組の発表の始めに実際の進み具合で見積もり直す。数字は飛ばさず、進む速さだけを変えて見積もりに寄せる (数字が大きく映っている間は ±8%、小さいときは ±20%、映っていない・候補カードで隠れている間は大きく)。前振り (実測約4.8秒) の間はほぼちょうど1秒ずつ減る
  - カメラが近くに寄って数字が大きく映っているときだけ、1秒ごとに小さな電子音が鳴る (近いほど大きい)
  - 動画のあと名前カードが装置にぶつかる瞬間に爆発する (オレンジの火の玉・火花・画面のフラッシュ・爆発音)。装置は消え、名札に戻る
  - 動画のあとは 00:01 で止まり、液晶が白く光る (最前列中央を動かさない回は最初から出ない)
- **順番**: 最前列中央の席は必ず**最後の3人**の中に入る。残り3人の名前を見せてから動画で明かすので、3人のうち誰が最前列の中央かが最後の見どころになる。ほかの席の順番はランダム
- 読み込みに時間がかかると「動画を読み込み中…」を表示する。再生を拒否されたり25秒待っても映像が出なかったりした場合は「タップで再生」で音付きのまま再試行できる。再試行も失敗した場合だけ「動画をスキップ」を表示する
- 動画の再生に失敗した理由はブラウザのコンソールに表示する。URL に `?debug` を付けると画面でも確認できる
- 効果音・BGM・動画は音付き。iPad / iPhone 向けに、席替えスタートを押した瞬間に動画を再生可能な状態にしている
- 中央の席を固定している回は、発表がないので動画も流れない。中央の席だけは2人組にせず、必ず1人で発表する (動画のあとは名前カードを出し、カメラと一緒に席へ飛び込む)
- 動画の再生中は裏の 3D の描画を止める
- 設定は `frontrow.js` の `FRONT_ROW` (席、3・2・1 と名前の表示秒、画面の四隅、文字の大きさ、最後から何番目か、終了画面を見せる時間など)

## ローカルで動かす

ES モジュールと Service Worker を使うので、`file://` ではなく HTTP サーバーで開いてください。動画のシークには **Range リクエストに対応したサーバー**が必要です (`python3 -m http.server` は非対応で、シークすると先頭に戻ります)。

```bash
npx http-server -p 8090 -c-1
```

Service Worker は動画をキャッシュせず、Range リクエストをそのままネットに通します。
起動時に3曲のBGM、効果音、司会者の声を準備します。最初のタップやクリックで音声再生を有効にし、音声ファイルは通常のファイルと同じようにキャッシュします。
